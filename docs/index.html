Extract & prepare

The model cannot repair a broken source.

Input: the included 81-page Arabic PDF. Output: UTF-8 text with PDF-page markers. Both files already live in data/.

Digital PDF

Try text extraction first. Inspect reading order, columns, Arabic letters, tables and numbers. Selectable text can still have broken character mappings.

Scanned or broken text

Render pages and use OCR. Our source needed Arabic Tesseract OCR. OCR may omit or misread words and figures; compare samples with the PDF.

Preparation: preserve the original PDF, normalize Unicode and line endings, remove decorative tatweel, keep useful headings and provenance. Do not silently rewrite policy, targets, or numbers. Check page counts and sample pages before embedding.

The existing extraction script saves a checksum and page offsets in data/extraction.json. The simple chatbot cites chunk IDs; page markers in text are not a guaranteed page citation for every chunk.

Normal setup uses the committed TXT. Re-running OCR is optional and needs Tesseract with Arabic language data plus the optional Python dependencies.

Chunk the text

Choose what the retriever is allowed to return.

Input: one long text. Output: smaller documents with IDs, source and character offsets. Small chunks can lose context; large chunks can dilute relevance and consume the context budget.

MechanismHow it worksTradeoff
Fixed charactersExact windows measured with string lengthSimple; may cut sentences
RecursiveTry paragraphs, then sentences/separators, then smaller piecesPreserves some structure; sizes and overlap vary
Token basedUse the target tokenizer to limit chunk lengthFits model budgets; tokens are not characters
Structure basedSplit on headings, sections, pages or code definitionsUseful boundaries; may need further splitting
SemanticDetect changes in topic, often with embeddingsExtra computation; tune and evaluate boundaries

Our baseline is 1,000 Unicode characters, 250 overlap, stride 750. A short Python loop makes the exact behavior visible. LangChain Document wraps each slice. Recursive splitters do not promise the same exact windows.

Computed windows for a 2,500-character sample. End offsets are exclusive; no redundant final overlap-only chunk.

Create embeddings

Turn text into numbers for search—not an answer.

An embedding model maps a chunk to a vector: a list of learned numerical features. Related meanings tend to be near one another in its representation space. Individual dimensions generally do not have a simple human-readable label.

“Support small businesses” → embedding model → [0.12, −0.31, …]
“Help entrepreneurs grow” → same model → [0.10, −0.28, …]

These numbers are illustrative. The application uses OpenAIEmbeddings with text-embedding-3-small. Document and query vectors must use the same embedding model and configuration. Matching dimensions alone is insufficient.

The embedding model and the answering LLM have separate jobs. Embeddings support retrieval; the LLM generates language. Adding a document to Chroma does not train either model.

Embed documents during ingestion. Embed each new query at search time. Changing the embedding model requires rebuilding the document vectors. Arabic/English cross-language retrieval must be evaluated, not assumed.
Show code / commands
from langchain_openai import OpenAIEmbeddings
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector = embeddings.embed_query("ما هي محاور الرؤية؟")
print(len(vector))

Store & compare

A vector database keeps vectors connected to evidence.

Chroma stores an ID, vector, original chunk text, and metadata. The local database persists under artifacts/chroma/; no database account is needed.

At search time, a query vector is compared with stored vectors. Vector databases may use approximate nearest-neighbor indexes for speed. Results are rankings, not proof that an answer exists.

cosine similarity = (q · d) / (‖q‖ × ‖d‖)

Cosine measures direction, typically from −1 to 1. Dot product is magnitude-sensitive unless vectors are normalized; Euclidean distance measures straight-line separation. Metric choice and score conventions matter.

Real calculation on invented 2D vectors—not a projection of actual text embeddings. Smaller cosine distance = closer; higher cosine similarity = closer.

We configure Chroma with cosine distance. Its similarity_search_with_score returns distance here. The app displays similarity as 1 − distance. Neither is a confidence percentage.
Show code / commands
store = Chroma(
    collection_name="vision2030",
    embedding_function=embeddings,
    persist_directory="artifacts/chroma",
    collection_metadata={"hnsw:space": "cosine"},
)
store.add_documents(docs, ids=chunk_ids)

Retrieve evidence

Inspect the search result before asking the LLM.

Retrieval is the process that embeds a query, searches the index, selects passages and returns evidence. A retriever does not write the final answer.

Illustrative ranking for a question about support for small businesses. These are teaching descriptions, not quotations from the source.

Increasing k can add missing evidence, but also noise, repeated overlap, latency and prompt tokens. Metadata filters can narrow sources. Hybrid search can combine lexical and vector signals; rerankers can reorder candidates. These are extensions, not required for our first chatbot.

Test an answerable question, a paraphrase, a question spanning a boundary, and a question outside the document. Read the passages before judging the answer.

Understand LLMs

Size, task and access are different dimensions.

Architecture

Encoder models represent input (often used for understanding/embeddings). Decoder models generate continuations. Encoder–decoder models map an input sequence to an output sequence. These are broad patterns, not exclusive product categories.

Behavior & access

Base models learn text patterns; instruction-tuned/chat models are adapted to follow requests. Reasoning-oriented models allocate more computation to some tasks. Models may be text-only or multimodal, hosted APIs or locally deployed open-weight models. Open weights do not automatically mean unrestricted licensing.

A parameter is a learned numerical weight inside a model. It is not a document, token, embedding dimension, context slot, or a request setting such as temperature. Training changes weights; ordinary RAG supplies evidence without changing them.

At 16 bits per weight, raw weights need roughly 2 bytes each. This excludes KV cache, activations and runtime overhead. Quantization can reduce weight storage with quality/performance tradeoffs. Mixture-of-experts models distinguish total from active parameters.

More parameters do not guarantee better results for your task. Compare Arabic quality, grounding, latency, cost and deployment constraints. Parameter counts for many proprietary models are undisclosed; we do not assign an invented count to the configured API model.

Instructions & context

The prompt tells the model what to do with the evidence.

The context window is the token budget a model can process for a request, subject to its input/output limits. Instructions, question, retrieved text, message history if included, and output capacity compete for space. Token counts depend on the tokenizer and language; characters are not tokens.

Toy budget: instructions 300 + question 100 + evidence + 800 output reserve. These capacities are hypothetical, not the configured model’s limit. Real apps count tokens with the appropriate tokenizer and use provider limits; some reasoning models also budget reasoning tokens.

Clear instructions specify scope, source use, language, citation format and abstention. They steer behavior; they cannot guarantee factuality or prevent all prompt injection. Retrieved text is untrusted data. Temperature 0 does not guarantee identical or correct answers.

Build the chain

Small functions, visible data, one responsibility each.

retrieve(question) → Document text + metadata
format evidence → prompt → ChatOpenAI → string parser

LangChain’s | composes runnable components. prompt | llm | StrOutputParser() formats messages, invokes the model, and extracts text. In our code, retrieval runs explicitly first so you can print and inspect it.

ask() joins the steps and returns the answer plus evidence. No agent decides which tool to call. No hidden conversation memory is added. A follow-up such as “what about it?” must be rewritten as a complete question.

Chunk citation checks only detect missing or unknown IDs. A valid ID does not prove the claim is supported. Compare the answer with the text and PDF.

Show code / commands
matches = retrieve(question, k=3)
context = json.dumps(matches, ensure_ascii=False)
chain = prompt | llm | StrOutputParser()
answer = chain.invoke({"question": question, "context": context})

Connect the frontend

The browser sends a question; the backend owns the key.

Textarea → POST /api/ask → Python ask() → JSON
JSON → answer + cited chunks + source text in the browser

FastAPI serves both the frontend and backend on the same origin. The browser sends {question, top_k}. The backend retrieves evidence and calls the LLM. It returns answer, matches and citation warnings.

The existing frontend uses plain HTML, CSS and JavaScript. It renders source text and model output with textContent. API credentials stay in .env on the backend.

Use “Retrieve only” to isolate the search stage, then “Ask Vision 2030” for the full chain. The source PDF remains available at /source.pdf.

Local teaching app: no login, rate limiting or production operations. API calls incur usage charges. Each question is independent.

Run the real pipeline

Clone, configure, inspect, index, search, answer, serve.

Use Python 3.11 or 3.12 for the new teaching path. Clone the repository, create a virtual environment, install requirements-simple.txt, copy .env.example to .env, and set your own API key. The PDF and TXT are already included.

Windows: use py -3.12 -m venv .venv and .\.venv\Scripts\Activate.ps1. If activation is blocked, run .\.venv\Scripts\python.exe directly. Use Copy-Item .env.example .env to copy configuration.

Open http://127.0.0.1:8000. The interactive walkthrough is at /guide/. Keep the terminal running. Never paste your API key into this HTML file.

Changing text, chunk size/overlap, or embedding model requires ingestion again. The script checks a signature and reuses an unchanged index. A changed source rebuilds this dedicated collection. Generation-model changes do not require re-embedding.
