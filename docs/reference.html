01 / CHUNKING

Split the document into fixed windows

Read the text before embedding it. We use static character chunking: at most 1,000 characters in each window and exactly 250 characters shared between adjacent windows. The stride is 750 characters.

A 2,500-character example
[0, 1000)
[750, 1750)
[1500, 2500)
075015002500

Offsets are zero-based and the end is exclusive. “Characters” means Python Unicode code points, not tokens or bytes. The loader removes a UTF-8 BOM and normalizes line endings to \n. It does not strip, summarize, or otherwise rewrite your document.

python -m rag_lab chunk

Open artifacts/chunks.json. It contains the original text slices, chunk IDs, character offsets, and a hash of the source document.

# Expected output pattern; N depends on your document.
Saved N chunks from M characters.
chunk-0001: [0, 1000) — 1000 characters
chunk-0002: [750, 1750) — 1000 characters
Checkpoint: artifacts/chunks.json
The core chunking loop
start = 0
while start < len(text):
    end = min(start + 1000, len(text))
    chunk = text[start:end]
    # Save chunk text, ID, start, and end.
    if end == len(text):
        break
    start += 1000 - 250

The complete runnable function is chunk_text() in rag_lab/chunking.py. Stopping when a chunk reaches the end avoids a redundant final window containing only overlap.

Checkpoint

Check that the final 250 characters of chunk 1 equal the first 250 of chunk 2. The final chunk can be shorter than 1,000 characters. A document of 1,000 characters or fewer produces one chunk.

Discuss: What happens when a sentence crosses a window boundary? Overlap preserves some nearby context, but this method does not understand sentence or paragraph boundaries.

02 / EMBEDDINGS

Turn each chunk into a vector

An embedding represents the chunk as a list of numbers. We save one vector per chunk using text-embedding-3-small. The source text and metadata stay beside the vectors so retrieved results can be read and cited.

python -m rag_lab embed

This step makes API requests in batches of up to 32 chunks. Open artifacts/index.json and inspect embedding_model, dimensions, chunks, and vectors.

Saved N embeddings, 1536 dimensions each.
Checkpoint: artifacts/index.json

The dimension above is the configured model’s default. The application records the actual dimension returned by the API. It normalizes vectors before saving them.

The API call
response = client.embeddings.create(
    model=settings.embedding_model,
    input=texts,
    encoding_format="float",
)
vectors = [row.embedding for row in
           sorted(response.data, key=lambda row: row.index)]

See OpenAIProvider.embed() in rag_lab/provider.py. No generation model is called at this stage. Whitespace-only windows keep their offsets but use a blank-text marker for embedding and are excluded from retrieval evidence.

Checkpoint

The number of vectors equals the number of chunks. Run the command again: a current index is reused without an API call. Use python -m rag_lab embed --force only when you intentionally want to re-embed.

Why a local JSON index? It makes storage and search visible without requiring a database account. Search scans the vectors in memory. This is intended for a small Vision 2030 document, not a large production corpus.

03 / RETRIEVAL

Find relevant passages before generating

Start with the example question below about the pillars of Saudi Vision 2030. Then ask about culture, economic diversification, or small businesses.

python -m rag_lab retrieve "ما هي محاور رؤية السعودية 2030؟" --top-k 3
Your question→Same embedding model→Cosine similarity→Top 3 chunks

Document embeddings are reused. Only the new question needs an embedding API call.

Read the terminal output or artifacts/last_retrieve.json. Each result includes a chunk ID, filename, score, offsets, and the full passage.

# The retrieval score for normalized vectors:
score = sum(q * d for q, d in zip(query_vector, document_vector))
# Sort highest score first, then keep top_k matches.
Similarity is not certainty. The highest-scoring passage may still be irrelevant. A score is not a confidence percentage, and top-k retrieval alone does not decide whether a question is answerable.
Checkpoint

No answer has been generated. Read the top passages yourself: do they contain the facts required to answer your question? If not, inspect the source and chunk boundaries before changing the prompt.

Try: Ask the same question using different wording. Then change --top-k 3 to --top-k 1. Notice that overlapping chunks can produce repeated evidence.

04 / THE COMPLETE PIPELINE

Connect retrieval, context, and generation

Chaining here means composing ordinary Python functions. No LangChain or other orchestration framework is required. The pipeline calls retrieval, packages the question and evidence, and asks the generation model for a grounded answer.

python -m rag_lab ask "ما هي محاور رؤية السعودية 2030؟" --top-k 3
Question→Retrieve→Evidence + instructions→Generate

Output: answer + retrieved passages + chunk citations + a pipeline trace.

Read the chain in the source
# rag_lab/pipeline.py
search = retrieve(settings, provider, question, top_k)
evidence = search["matches"]
answer = provider.generate(search["question"], evidence)

provider.py holds the instructions separately from source text. It uses the Responses API and asks the model to answer only from evidence, cite IDs such as [chunk-0001], and say when evidence is insufficient.

Open artifacts/last_ask.json. Compare the answer with matches. Citation warnings flag missing or unknown chunk IDs; they do not prove whether the cited text supports a claim.

Checkpoint

Ask one supported question and one question your document cannot answer. Check whether the first answer cites supporting evidence and the second acknowledges missing information.

Important limitation: Prompt instructions reduce unsupported answers but cannot guarantee factuality or prevent every prompt-injection attempt. Retrieved document text is treated as untrusted evidence. This local teaching app is not a production deployment.

const response = await fetch('/api/ask', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({question, top_k: 3})
});
const result = await response.json();

See frontend/app.js. It displays source and model text using textContent, not HTML injection. The browser never needs your API key.

Checkpoint

You can also open the interactive API reference and this guide through the server. If port 8000 is busy, use python -m rag_lab serve --port 8001 and update the URLs accordingly. Stop the server with Ctrl + C.

06 / EVALUATE

Test what the assistant actually knows

Prepare three questions from the Vision 2030 document. Write the expected evidence before running them.

TestWhat to inspect
A fact directly stated in the documentDoes the correct passage appear? Does the answer preserve the fact?
A question spanning a chunk boundaryDoes the 250-character overlap help? Are multiple passages necessary?
A question outside the documentDoes the model acknowledge missing evidence rather than inventing an answer?

Compare top-k values of 1 and 3. More context can add useful evidence, but can also add noise and duplicated text. Changing the generation model cannot repair missing source facts.

Run the automated checks

python -m pip install -r requirements-dev.txt
python -m unittest discover -v

Tests use a fake embedding/generation provider. They check exact boundaries, overlap, stale indexes, vector dimensions, citations, and HTTP routes. They do not use an API key or measure real semantic quality.

Checkpoint

You can explain every stage, show a supported answer, demonstrate an unsupported question, and identify one improvement you would make before production.

WHEN SOMETHING GOES WRONG

Use the checkpoint to find the problem

What you seeWhat to do
Document not foundRestore the included UTF-8 OCR text at data/saudi_vision2030_ar.txt or set DATA_PATH.
Missing or stale chunksRun python -m rag_lab chunk, then python -m rag_lab embed.
Stale index or different modelRe-run embed. The query and document must use the same embedding model and dimensions.
Embedding or generation request failedCheck the key, model access, account quota, and connection. Never share the key in screenshots or issues.
Wrong passagesRead the document and chunk offsets. Try a more specific question and compare top-k values.
Answer is unsupportedInspect retrieval first. Verify citations manually. Tighten the instruction or narrow the task.
Frontend cannot connectStart python -m rag_lab serve and open its URL. Do not double-click frontend/index.html.
Import/module not foundUse the virtual environment and run commands from the repository root. Install requirements.txt.
